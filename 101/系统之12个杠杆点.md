| **1**   |  <br>存在论层<br><br>“我在玩什么游戏？为什么？”  | **超越范式** (Transcending Paradigms)       | 范式本身仍是“规则”，而超越范式意味着摆脱对所有范式的执着，进入“空”的境界，拥有绝对的灵活性。 | * 极度的自由度<br><br>  <br><br>* 能从根本上重塑整个现实<br><br>  <br><br>* 不受任何既定思维框架的束缚 | * 极难达成，属于哲学/禅修层面<br><br>  <br><br>* 容易陷入虚无主义或失去行动目标           |
| **2**   |                                  | **范式** (Paradigms)                      | 范式产生目标。它是系统产生的基础——即全社会公认的、根深蒂固的信念体系。             | * 一旦改变，整个系统会发生翻天覆地的重组<br><br>  <br><br>* 这种改变具有持久且深远的影响                  | * 具有极强的抗拒性，守旧势力通常会拼死捍卫旧范式<br><br>  <br><br>* 改变周期极长           |
| **3**   |   目的论层<br><br>“系统为何而动？如何自我演化？”   | **目标** (Goals)                          | 目标定义了系统的“心”。自组织是为了实现目标，改变目标会使系统内所有行为发生质变。        | * 能够迫使系统内的所有子模块重新对齐<br><br>  <br><br>* 只要目标明确，系统会自己寻找出路                  | * 若目标设定错误（如只追求GDP），会产生巨大的负外部性<br><br>  <br><br>* 容易导致为了结果不择手段 |
| **4**   |                                  | **自组织** (Self-Organization)             | 规则定义行为，而自组织能够改变规则。它是系统进化的力量，让系统具备创造新结构的能力。       | * 增强系统的复原力和适应性<br><br>  <br><br>* 能够催生出意想不到的创新和进化                        | * 具有不可预测性，管理层往往害怕失去控制感<br><br>  <br><br>* 可能演化出具有破坏性的新结构      |
| **5**   |                                  | **规则** (Rules)                          | 规则是系统的“激励机制”。信息流只是在规则下运行，改变规则能直接重塑人的动机。          | * 成本低、见效快（如法律修改、激励机制变革）<br><br>  <br><br>* 能迅速改变系统参与者的边界行为               | * 若规则过于复杂，会导致系统僵化<br><br>  <br><br>* 规则执行的公正性难以保证             |
| **6**   | 操作论层<br><br><br>“在不动根本前提下，如何优化？” | **信息流** (Information Flows)             | 即使回路存在，如果没有反馈信息，回路也无法工作。重新打通信息反馈能让系统“醒过来”。       | * 无需改变物理结构即可大幅提升系统效率<br><br>  <br><br>* 能让沉默的利益相关者获得发言权                  | * 信息过载或误导性信息会导致决策偏差<br><br>  <br><br>* 既得利益者往往会封锁关键信息         |
| **7**   |                                  | **增强回路** (Reinforcing Feedback Loops)   | 调节回路是守旧，而增强回路是“引擎”。控制其增长速度比单纯调节单个变量更有力。          | * 能产生指数级增长或爆发式改进<br><br>  <br><br>* 在系统起步阶段提供核心动力                        | * 极易失控，导致系统崩溃（如通货膨胀、恶性竞争）<br><br>  <br><br>* 难以停下来            |
| **8**   |                                  | **调节回路** (Balancing Feedback Loops)     | 比起调整延迟，修复或增强反馈回路的灵敏度能让系统更稳定，预防危机发生。              | * 维持系统稳定，防止崩溃<br><br>  <br><br>* 具有自我修复和纠偏的功能                            | * 往往被忽视，直到系统出问题才被察觉<br><br>  <br><br>* 过度调节可能导致系统失去活力         |
| **9**   |                                  | **时间延迟** (Delays)                       | 结构是静态的，而延迟决定了动态响应。改变延迟比改变结构更容易微调系统的稳定性。          | * 减少系统震荡，提高预测准确性<br><br>  <br><br>* 给决策者留出反应缓冲期                          | * 物理上的延迟往往难以改变（如树木生长、人才培养）<br><br>  <br><br>* 延迟过长会导致反应过激     |
| **10**  |                                  | **存量流量结构** (Stock-and-Flow Structures)  | 物理结构决定了系统的上限。这比单纯调整缓冲池（大小）更具全局性。                 | * 从物理设计上优化效率，具有长期稳定性<br><br>  <br><br>* 减少不必要的资源损耗                       | * 物理重建成本极高，周期极长<br><br>  <br><br>* 一旦建成，灵活性极差（如城市管网）          |
| **11**  |                                  | **缓冲池** (Buffers)                       | 比起具体的参数值，缓冲池的大小决定了系统的鲁棒性（耐操程度）。                  | * 增加系统的容错率，防止突发扰动导致崩溃<br><br>  <br><br>* 提供平滑的过渡空间                       | * 维持大型缓冲池（如库存）的成本很高<br><br>  <br><br>* 过大的缓冲池会掩盖系统深层问题        |
| **12**  |                                  | **参数** (Constants, Parameters, Numbers) | 处于系统的最表层，通常是人们最关注但影响力最小的地方（如税率、补贴额）。             | * 调整最为简便，易于量化和执行<br><br>  <br><br>* 能够进行精确的微调                            | * 很少能改变系统性质<br><br>  <br><br>* 往往陷入“头痛医头”的循环，治标不治本            |
