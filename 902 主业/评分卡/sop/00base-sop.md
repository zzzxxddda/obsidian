要从跑通一张完整申请评分卡的流程，再把 AUC 从“勉强能用”推到业务可用甚至优秀，核心在于**带着业务逻辑做精细化迭代，而不是无脑调模型**。下面是完整的路径，你可以照着一步步实现。

---

## 第一阶段：极简跑通全流程（建立基线）

先用最标准、最自动化的方式，把一条完整流水线搭起来，拿到基线 AUC/KS。

### 1. 准备数据
- `target`：0/1（好/坏），定义要清晰（如逾期90天+）。
- 特征：基础信息（年龄、收入、工作年限等）、多头借贷、征信查询等。
- **必须划分时间窗口**：训练集（如2023年1-6月）、OOT验证集（如2023年7-8月）。

### 2. 一键自动化分箱 + 建模
用 `scorecardpy`，几行代码就能跑通全流程，帮你自动完成分箱、WOE转换、变量筛选和逻辑回归。

```python
import scorecardpy as sc
import pandas as pd

# ----- 读取数据 -----
train = pd.read_csv('train.csv')  # 包含 target 和特征
test = pd.read_csv('test.csv')

# ----- 自动分箱（强制单调）-----
bins = sc.woebin(train, y="target",
                 bin_num_limit=8,           # 最多8箱
                 min_perc_coarse_bin=0.05,  # 每箱不低于5%
                 positive="bad|1",
                 method="tree")             # 决策树切点

# ----- 转换为WOE值 -----
train_woe = sc.woebin_ply(train, bins)
test_woe = sc.woebin_ply(test, bins)

# ----- 变量筛选（基于IV）-----
# 保留 IV > 0.02 的变量
train_selected = sc.var_filter(train_woe, y="target", iv_limit=0.02)

# ----- 逻辑回归建模 -----
from sklearn.linear_model import LogisticRegression
X = train_selected.drop(columns=['target'])
y = train_selected['target']
model = LogisticRegression(penalty='l2', C=1.0, solver='sag')
model.fit(X, y)

# ----- 评估基线 -----
from sklearn.metrics import roc_auc_score
y_pred = model.predict_proba(X)[:, 1]
baseline_auc = roc_auc_score(y, y_pred)
print(f'Baseline AUC: {baseline_auc:.4f}')
```

此时你应该得到了一个**单调、稳定、可解释**的评分卡基线。通常基线 AUC 在 0.65-0.75 之间，视数据质量而定。

## 第二阶段：精细调优，稳定提升 AUC

提升 AUC 的手段，都要在**不破坏单调性、不降低业务可解释性**的前提下进行。按效果排序如下：

### 策略1：分箱的“精修”，这是最大增量
自动分箱追求的是“整体较优”，但不少变量还能人工优化。

- **手动调整切点**：画出每个变量的 IV 曲线和 WOE 趋势，把自动切点向风险变化的“拐点”微调。  
  例如收入从0-3000和3000-8000的分界点，如果业务规定5000是低收入线，就调整到5000，同时看IV损失是否可接受（< 0.005）。
- **放宽单调性限制（慎用）**：某些变量天然倒U型（如年龄），若自动硬单调导致 IV 过低，可尝试分箱后合并成“年轻、中、老”三箱，允许非单调，然后进模型作为**哑变量**，能大幅提升 AUC。
- **缺失值独立成箱**：不要填充。确保缺失单列一箱，并检查其 WOE 是否显著偏离0，若是，说明缺失本身是强特征。

### 策略2：特征工程——寻找“隐藏的黄金”
原始变量信息量有限，需构造业务衍生变量。

- **比率类**：负债/收入（DTI）、月还款/收入、总负债/总资产。这类变量IV通常比单个高0.05-0.1。
- **稳定性/趋势类**：近3个月查询次数均值、最近一次借款金额变化率、额度使用率趋势（上升/下降）。
- **组合特征**：学历_高且收入_低，这种交互项可用决策树分箱后的变量进行交叉，再用卡方分箱合并。
- **时间窗口滚动统计**：过去6个月最大逾期天数、近3个月多头借贷平台数。

**小技巧**：先用 LightGBM 跑一遍特征重要性，筛选出 Top 20 重要特征，再针对性构造衍生变量，然后替换回逻辑回归，AUC 通常能涨 0.02-0.04。

### 策略3：模型层面的精细化
评分卡模型必须是逻辑回归，但可以精细调教。

- **逐步回归 + 业务筛选**：用向前/向后逐步回归，保留 p 值<0.05 且系数符号符合业务逻辑的变量。  
  即使某变量 IV 高，如果系数为正（风险越高分越高），也要强行剔除或重分箱。
- **正则化参数调优**：`C` 不要默认1，在 0.01、0.1、1、10 上网格搜索，选 OOT 验证集 KS 最高的。
- **样本权重**：如果好坏样本不平衡（如坏样本仅 5%），可以给坏样本更高权重，让模型更重视对坏账的识别，OOT 上的 AUC 通常更稳定。

### 策略4：多模型融合做辅助（不破坏主评分卡结构）
如果你想榨取最后一点 AUC，又不违背监管对可解释性的要求，可以在逻辑回归评分卡**外层**轻量集成：

- **GBDT + LR 混合**：用 XGBoost/LightGBM 做特征提取（如上文），输出叶子节点位置作为新特征，拼入原始特征后再训练 LR。  
  这实质是用树模型的非线性能力给 LR 提供强特征，最终产出仍是 LR 评分卡，AUC 往往能逼近纯 GBDT。
- **模型堆叠**：但多数消费金融场景直接不允许，仅作内部预警模型使用。

### 策略5：拒绝推断与半监督学习（当有拒绝样本时）
若建模样本仅包含“通过申请”的客户，高分但被拒的样本缺失，会导致 AUC 虚高且有偏。引入**拒绝推断**（如简易的 Parcelling 法）对拒绝样本打上推断标签后重新分箱建模，能使线上真实 AUC 提升 0.03-0.05。

## 第三阶段：评估与迭代的闭环

每次调整后，必须严格检查：

| 指标 | 要求 | 说明 |
| :--- | :--- | :--- |
| **AUC** | 训练和OOT差距<0.05 | 过大则过拟合 |
| **KS** | 训练 KS 不宜超过 0.45 | 过高可能过拟合 |
| **WOE单调性** | 所有入模变量 WOE 单调 | 打破必须业务能解释 |
| **PSI (稳定性)** | 训练 vs OOT 每个变量<0.1 | 超限的变量要重分箱或剔除 |
| **系数方向** | 与 WOE 单调方向一致 | 保证分越高风险越低 |

**迭代路线图**：  
基线跑通 → 分箱微调(AUC+0.01) → 构造衍生特征(+0.02~0.03) → 逐步回归精选变量(+0.01) → OOT调参/权重(+0.01) → 最终模型。
